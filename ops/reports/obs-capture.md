# OBS capture integration

Tested 2026-09-12 with portable OBS 32.2.2, Chrome 152 and the validated Ene Cyber legs VRM. [Structured capture evidence](obs-capture-smoke.json) records both profiles, native source dimensions, computed crops and changing scene screenshots.

`node scripts/obs_capture_smoke.mjs` passed on actual Windows Graphics Capture, using a visible, owned Chrome window with its native viewport. The test prohibited physical media access and injected known face rotations into actual Ene. No recording, public stream or microphone was started. Both scenes contain only the cropped avatar composition; landscape and portrait screenshots were visually inspected. The test disables its sources and closes its browser afterward.

The production helper reads short-lived geometry from the app's local `/api/output-layout` endpoint. Only title, composition and viewport/canvas rectangles are stored, in memory for 5.5 seconds; no camera frames, audio or avatar bytes are sent. Same-origin JSON, loopback host checks, size/bounds limits and tests protect this small interface. The helper matches a single visible Ene output, selects the OBS-returned window identifier, waits for its dimensions and computes the browser/margin crop. Reattach after changing window size or composition. Ambiguous outputs and incompatible geometry stop attachment.

The measured native source was 1628×1009, with a 1086×586 CSS viewport. Browser controls required a 131-source-pixel top crop. The landscape canvas used 33-pixel side crops; portrait used 567-pixel side crops. OBS composition/output remains exactly 1280×720 or 720×1280 at 30 fps. The portrait source content was about 494×878 physical pixels and is upscaled to the output dimensions; use a larger visible output on a taller display for more native detail.

An initial automation run used an emulated browser viewport, which did not describe the real window's clipped client area. Visual inspection caught remaining browser chrome. The test now uses `viewport: null` and verifies the native window. That failed run is not accepted evidence. A separate startup handoff issue was fixed by explicitly awaiting current published geometry before attachment.

## Configuration and limits

- `scripts/setup_obs.py` creates two portable profiles and a two-scene collection while preserving saved scene/profile edits. The baseline is opaque Window Capture, WGC method 2, strict title priority 1, cursor and source audio off. Default desktop/microphone devices are absent.
- The recording configuration is MKV, x264 CRF 23, veryfast, 30 fps. [Short actual recordings](obs-recording.md) now pass in both orientations with AAC reference audio, zero OBS render/encoder skips, MP4 remux and Chrome playback. Sustained live camera/voice quality and timing remain open.
- The OBS helper connects to `127.0.0.1:4455` with the private generated password. OBS's own WebSocket listener binds to network interfaces, not exclusively loopback; authentication remains required. The password/config are inside ignored `.tools/`, and are not exported with scene guidance. No streaming credentials were configured.
- A dedicated output popup is the baseline. Window-title matching selects/reacquires a window; it does not police content after that window is acquired. [Measured lifecycle behavior](obs-window-lifecycle.md) confirms tab changes remain captured, same-title replacements can be acquired, minimizing blanks and hiding freezes. Stop output and disable the source before leaving Clean view, navigating or changing the captured window.
- OBS Virtual Camera registration and consumer verification are pending. The reviewed 32/64-bit DLLs have valid OBS Project signatures. `scripts/install_obs_virtual_camera.ps1` validates their exact hashes, preserves any existing camera registrations, and requests Windows administrator confirmation only for missing registrations. The attempted registration returned Windows' “operation was canceled by the user”; neither architecture is registered. No automatic retry is scheduled. `Install OBS Camera.cmd` provides the reviewed helper for a later interactive attempt. [Installation status](obs-virtual-camera-install.json) is separate from video-consumer acceptance.

Reference implementation: [OBS 32.2.2 window capture](https://github.com/obsproject/obs-studio/blob/32.2.2/plugins/win-capture/window-capture.c), [window matching helpers](https://github.com/obsproject/obs-studio/blob/32.2.2/libobs/util/windows/window-helpers.c), [OBS launch parameters](https://obsproject.com/kb/launch-parameters), and [OBS WebSocket protocol](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md).
