# Language rules for this repository

Use ASD-STE100 Simplified Technical English (STE) for all English text that you write for the user. This rule applies to chat replies, task plans, reports, documentation, code comments, UI text, commit messages, and pull requests. Keep exact API names, code, file paths, quoted source text, and required legal text.

Use [ASD-STE100 Issue 9](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf) as the authority. Its [official FAQ](https://www.asd-ste100.org/STE_faq.html) explains the controlled dictionary and technical terms. Do not claim full STE compliance until a person checks the text against both parts of the standard.

- Use approved dictionary words with their approved meanings and parts of speech. Use project terms as technical nouns or technical verbs only when the standard permits them.
- Use American English spelling. Use one term for one item or action. Define each project term at first use.
- Write one topic in each sentence. Keep descriptions at 25 words or fewer and procedure steps at 20 words or fewer.
- Use active voice. In procedures, use direct commands. Put a necessary condition before its command.
- Use short noun groups. Split groups of more than three nouns. Avoid unnecessary `-ing` forms and ambiguous pronouns.
- Use lists for sequences and groups of related facts. Keep each step to one action, unless actions must occur together.
- Preserve numbers, units, limits, warnings, uncertainty, and source references. Do not simplify away a technical condition.
- Review each new or changed English sentence before delivery. Check sentence length, terms, voice, and meaning. Use the official dictionary for uncertain words.

The standard controls English prose. Code syntax, identifiers, external quotations, and source titles keep their exact form.
